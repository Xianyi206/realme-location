# 定点助手 1.2 交互变更与验收边界

1.2 按日常任务拆分页面，分别展示待使用的目标坐标和服务当前生效的坐标。

## 对照依据

[Android 布局与导航模式](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns)建议用底部导航承载 3–5 个同级目的地。本应用据此采用「定位」「地点」「设置」。[设置设计指南](https://developer.android.com/design/ui/mobile/guides/patterns/settings)用于区分偏好设置与日常主要操作。[应用结构指南](https://developer.android.com/design/ui/mobile/guides/layout-and-content/app-anatomy)用于整理顶部标题、内容区与导航关系。

## 最终页面分工

| 任务 | 1.2 的路径和行为 |
| --- | --- |
| 首次准备 | 首次引导列出三项要求；可逐项打开系统设置并查看返回后的状态，也可跳过整理地点 |
| 模拟定位 | 首页查看运行状态与目标；主按钮固定在底部，开始和停止有明确入口 |
| 管理多个地点 | 独立地点簿，直接展示、搜索；点卡片编辑，右侧使用，更多菜单删除 |
| 采集和保存 | 独立编辑页填写名称，选择当前位置、地图或手动坐标，底部保存 |
| 换地点 | 选择后回到首页；尚未确认前，当前模拟坐标保持原值；点击切换才更新 |
| 停止 | 首页停止按钮；地点/设置页运行条；系统运行通知 |
| 防止误操作 | 未保存返回确认，删除确认，输入错误留在编辑页修正 |

视觉采用统一留白、文字层级、卡片及绿色主操作，导航保留文字标签。按钮使用至少约 48–52 dp 的触控区域，内容区滚动，主操作固定。系统栏和键盘留出空间；从搜索页切换主页面时收起键盘。这些是代码实现意图，实际渲染仍需原生运行确认。

应用保留旧地点文件格式、包名和签名，提高版本号。地点完整编辑增加了独立的存储回归案例，检查稳定标识及原保存时间保留。选中目标与运行服务分别读取各自状态，不用新输入冒充当前运行坐标。

## 验证与未验证

44 个 Java 核心案例已通过，覆盖坐标边界、新采样筛选、存储重开与编辑以及模拟会话的失败清理。APK 编译、对齐与签名校验已通过。地图浏览器测试的结果和源码哈希以 Release 附件 `verification.json` 为准。

地图测试等待实际点击位置的地图块加载，并验证未加载区域不能选点。

最终交互效果仍需手机运行和用户反馈验证。
