# 定点助手 1.2.0 · 交互重做版

为 Android 手机提供固定坐标模拟，并在本机保存多个可命名的地点。1.2 将操作拆成「定位」「地点」「设置」三个页面，新增和编辑地点使用独立页面。

这是待实机验收的测试版。尚未运行原生界面验收；编译和核心逻辑测试不能证明手机布局、权限跳转或浏览器定位已经通过。

## 安装和首次设置

1. 将 `定点助手-1.2.0.apk` 传到手机，用文件管理器打开安装。与此前版本包名和签名一致，版本号已提高；请直接覆盖更新，保留已存地点，勿先卸载。覆盖升级仍待实机验证。
2. 首次打开会进入设置引导。在系统开发者选项中，将「选择模拟位置信息应用」设为「定点助手」。如开发者选项未显示，可在「关于本机 / 版本信息」连续点击版本号启用；realme 不同版本的名称可能不同。正常使用无需 USB 调试。
3. 允许应用使用期间的精确位置，并开启手机定位开关。三个状态完成后点击「完成设置」。也可点「稍后设置，先看看」先整理地点。
4. 建议允许运行通知，以便在通知栏停止模拟。如果切换浏览器后服务停止，检查 realme 的应用电池管理和后台运行设置。

## 三个页面怎样使用

| 页面 | 用途 | 常用操作 |
| --- | --- | --- |
| 定位 | 查看当前模拟状态、目标地点并控制运行 | 选择地点 → 开始模拟；随时停止 |
| 地点 | 查看、搜索和管理保存的位置 | 右上角 ＋ 新增；点卡片编辑；点「使用」选中 |
| 设置 | 权限准备、常用网页及手机设置帮助 | 点击待完成项目进入相应系统设置 |

「目标地点」是准备使用的位置。「当前生效」显示服务正在提供的坐标。选择、保存或编辑地点后，需要明确点击「开始模拟」或「切换到目标地点」才会改变模拟坐标。

## 记录当前位置、命名并保存

1. 在定位页点「记录当前位置」，或在地点页点右上角 ＋，进入编辑页后点「读取当前位置」。
2. 如果模拟正在运行，会先询问是否停止并继续。确认后才采集手机的新位置。
3. 读取期间最多等待 15 秒，可以继续填写名称。成功后显示经纬度、采集时间和估计精度；未取得新位置时显示错误，保留原有输入。
4. 填写「公司门口」「家」等名称，然后保存。应用记录坐标，名称由你填写，不自动查询街道地址。
5. 重复操作即可保存多个地点。在地点页搜索名称，点「使用」返回定位页，再点「开始模拟」。

也可以在编辑页手动填写经纬度，或从地图选点。地图返回后仍需保存；未加载地图的区域不能选点。

编辑：点地点卡片或右侧 ⋮ →「编辑地点」，可改名或改坐标。返回时若有未保存修改，会询问是否放弃。删除：⋮ →「删除地点」并确认；删除记录不会停止正在运行的模拟。

最多保存 1000 个地点，名称最多 40 字，同名记录各自保留。1.2 沿用原存储文件格式。关闭应用不会清除地点；卸载或清除应用数据会删除记录，本版没有导入导出功能。

## 模拟后切换浏览器

模拟开始后，自行切换浏览器；也可在设置中保存常用网页地址，再从定位页快捷打开。允许浏览器及网页获取位置，必要时刷新页面。应用向 Android 的模拟定位接口提供坐标，浏览器实际收到的位置仍需要在手机上核实；应用不会自动提交签到。

停止可在定位页、其他主页面底部的运行条，或运行通知中操作。停止后浏览器可能保留位置缓存，请刷新并重新获取。若恢复异常，将系统模拟位置应用设为「无」，必要时重启手机。

## 使用边界和数据

- 坐标采用 WGS84。高德、腾讯、百度等来源可能使用不同坐标系，本版不转换，不能直接混填。
- 新位置采集会过滤带模拟标记和过期的样本，优先等待精度在 25 米以内的结果；超时可采用本次最优样本。显示的精度是系统估计值。
- 模拟位置保留 Android 的模拟标记。网页是否识别或允许签到不能保证，应用显示正在模拟也不代表签到成功。
- 仅支持固定坐标，无路线模拟或开机自动运行。后台持续运行及服务清理仍待 realme 验证。
- 地点、坐标、采集时间、精度及常用网址仅保存在本机，关闭云备份，无账号或广告。打开地图会向 OpenStreetMap 请求相应区域的地图块。
- 地图使用随包附带的 Leaflet 1.9.4，许可见 `THIRD_PARTY_LEAFLET.txt`，保留 OpenStreetMap 署名。

## 源码和验证

本仓库包含应用源码、构建脚本和测试。交互说明见 [docs/UI-1.2.md](docs/UI-1.2.md)，版本说明见 [docs/RELEASE-1.2.0.md](docs/RELEASE-1.2.0.md)。安装包作为 GitHub Release 附件提供，不放入 Git 历史；发布验证范围以附件 `verification.json` 为准。

- `scripts/test_core.py`：坐标校验、新位置筛选、地点存储、会话清理，共 44 个已通过案例。
- `scripts/test_map.py`：在桌面 Chrome 的手机尺寸视口测试实际地图 HTML/CSS/JS；不验证安卓宿主界面。
- `scripts/test_native_ui.py`：供一次性安卓模拟器使用的验收脚本，本次未执行，不能当作通过证据。
- `scripts/build_apk.py`：通过 Android SDK 35.0.0 和 JDK 17 编译、对齐、签名并验证 APK。Android 最低版本 8.0，目标 SDK 35。

Windows 构建需要 Python 3、JDK 17，以及 Android SDK Platform 35 和 Build Tools 35.0.0。设置 `JAVA_HOME` 为 JDK 17 路径，`ANDROID_HOME` 为 SDK 路径，然后在仓库目录运行：

```powershell
python scripts/test_core.py
python scripts/build_apk.py
```

构建不使用 Gradle，输出为 `build/DingDianHelper-1.2.0.apk`。以上命令适用于手动终端；在有隔离执行要求的自动化环境中，通过该环境的任务启动器执行。地图浏览器测试还需要 Python Playwright 和 Google Chrome；原生测试仅面向脚本指定的一次性模拟器，会清空该模拟器上的应用测试数据。

本地开发签名保存在项目 `.keys/`，不会提交到 Git 或装入源码压缩包。后续覆盖更新需保留同一签名。首次自行构建会生成新的开发签名，不能用它覆盖安装原作者签名的安装包。
